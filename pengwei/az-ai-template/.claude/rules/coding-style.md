# 代码风格规范

## 📦 依赖版本稳定性管理

### 🎯 核心原则

1. **稳定版本优先，最新版本其次**
   - ✅ **优先使用经过验证的稳定版本**
   - ⚠️ 最新版本必须在测试环境验证后才能升级
   - ❌ 禁止在未经测试的情况下直接安装最新版本

2. **自动工作流中的依赖安装**
   - ✅ **Agent 可自主安装推荐版本清单中的依赖**（无需确认）
   - ⚠️ 安装清单外的依赖时，应先查阅官方文档确定稳定版本
   - ❌ 禁止安装已知有问题的版本

3. **MCP 工具选型规范**
   - ✅ 优先选择有 MCP 集成的工具（如 shadcn/ui）
   - ✅ 测试前必须先连接 MCP 确认功能可用
   - ✅ 不使用时必须卸载包并清理 MCP 配置
   - ❌ 禁止 MCP 配置残留

4. **遇到兼容性问题按标准流程处理**
   - ✅ 第一步：查阅依赖问题速查文档
   - ✅ 第二步：使用推荐的稳定版本
   - ⚠️ 第三步：如果速查表中没有，最多尝试 3 次解决
   - ❌ 禁止超过 3 次盲目试错

> 详细文档：[依赖管理与工具选型指南](./.claude/docs/development/dependency-management.md)

## 🗄️ 数据库配置规范

### 开发环境

- ✅ 优先使用 `SHENTONG_MIDDLEWARE_MONGO_URI` 系统环境变量
- ✅ `.env.local` 作为项目默认配置（用于 Docker 构建）
- ✅ 开发时自动同步 `.env.local` 为系统环境变量（避免多开发者手动配置）
- ⚠️ 推送前检查 `.env.local` 变更，确认是否需要提交

### 部署环境

- ✅ Dockerfile 中的 `ENV DATABASE_URL` 用于生产环境
- ✅ K8s 集群内的数据库地址由运维团队配置

### 多开发者协作

- 每位开发者首次运行 `npm run dev` 时，系统自动同步 `.env.local`
- 推送代码前检查 `git diff .env.local`，确认配置变更
- 如果是个人开发环境，评估是否需要提交到仓库
