## 用户输入

```text
$ARGUMENTS
```

## 执行目标

作为需求分析指挥官，调用**架构专家（architecture-planning-expert）**深度理解用户需求，并安排对应的专家完成开发。

## 执行步骤

### 步骤 0: 调用架构专家

直接调用架构专家进行需求分析：

```
请调用 architecture-planning-expert agent，深度理解以下需求并安排对应的专家完成开发：

需求内容：$ARGUMENTS

架构专家需要：
1. 深度分析需求的业务目标和技术可行性
2. 识别涉及的功能模块和技术栈
3. 拆解任务并确定优先级
4. 安排对应的专家（frontend-expert、backend-expert等）执行开发
5. 协调专家之间的协作
```

### 步骤 1: 架构专家职责

架构专家将执行以下职责：

#### 1.1 需求深度分析

- **业务目标理解**：明确需求的业务价值和用户期望
- **技术可行性评估**：基于项目技术栈评估实现难度
- **依赖关系分析**：识别涉及的现有模块和需要新增的功能
- **风险识别**：识别潜在的技术风险和实现难点

#### 1.2 任务拆解与规划

- **模块拆分**：将需求拆分为独立的功能模块
- **优先级排序**：确定任务的执行顺序（P0/P1/P2）
- **并行策略**：识别可以并行开发的任务
- **资源分配**：为每个任务分配合适的专家

#### 1.3 专家协调

根据任务类型安排对应专家：

| 任务类型 | 安排专家 | 说明 |
|---------|---------|------|
| 前端页面开发 | frontend-expert | React/Next.js组件、UI实现 |
| 后端API开发 | backend-expert | API Routes、数据库、服务端逻辑 |
| 完整功能开发 | frontend + backend | 前后端协作开发 |
| 架构设计 | architecture-planning-expert | 系统架构、模块设计 |
| 测试编写 | test-expert | E2E测试、单元测试 |
| 质量检查 | qa-expert | 构建验证、功能验证 |

### 步骤 2: 开发执行监控

架构专家作为技术总监，负责：

- **进度跟踪**：监控每个任务的执行状态
- **质量把关**：确保交付物符合需求规格
- **问题协调**：解决开发过程中的技术问题
- **跨层协作**：协调前后端专家的接口对接

### 步骤 3: 交付与验证

- **功能验证**：确认所有需求已实现
- **代码质量**：确保代码符合项目规范
- **文档更新**：更新相关文档（如需要）
- **总结报告**：生成开发完成报告

## 使用场景

### 场景1：新功能开发

```bash
/require 我需要增加一个用户评论功能，支持评论、回复和点赞
```

架构专家将：
1. 分析评论功能的数据模型
2. 设计前后端API契约
3. 安排backend-expert开发API
4. 安排frontend-expert开发UI组件
5. 协调测试和质量验证

### 场景2：现有功能优化

```bash
/require 优化首页加载速度，现在首屏加载需要5秒，目标2秒内
```

架构专家将：
1. 分析当前首页性能瓶颈
2. 制定性能优化方案
3. 安排对应专家执行优化
4. 验证优化效果

### 场景3：Bug修复

```bash
/require 用户登录后在某些情况下会话丢失，需要排查并修复
```

架构专家将：
1. 分析问题根因
2. 安排backend-expert修复后端问题
3. 安排frontend-expert优化前端状态管理
4. 协调测试验证

### 场景4：技术债务清理

```bash
/require 重构用户管理模块，当前代码耦合严重难以维护
```

架构专家将：
1. 分析现有代码结构
2. 设计重构方案
3. 安排专家执行重构
4. 确保功能不受影响

## 与其他命令的区别

| 命令 | 用途 | 工作流 | 适用场景 |
|-----|------|-------|---------|
| `/require` | 需求分析与专家协调 | 简化流程 | 日常开发、功能迭代 |
| `/az-coding` | 完整9阶段工作流 | 标准化全流程 | 复杂项目、新功能开发 |
| `/bug` | Bug分析处理 | 快速定位修复 | 问题排查、故障修复 |
| `/az-init` | 环境初始化 | 一次性配置 | 项目启动、环境搭建 |

## 行为规则

- **简化优先**：相比完整工作流，简化流程提升效率
- **专家协调**：架构专家负责协调，具体工作由对应专家执行
- **质量保证**：确保交付物符合需求和质量标准
- **灵活适应**：根据需求复杂度调整流程
- **可追溯性**：保留需求分析和开发记录

## 自动模式支持

如果用户输入包含"全自动"关键词，架构专家将：

- 自动完成需求分析
- 自动拆解任务
- 自动安排专家
- 自动执行开发
- 自动验证交付

无需任何用户确认，完全自动化执行。
