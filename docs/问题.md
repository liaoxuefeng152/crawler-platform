三、核心需求
3.1、前端整体目标
1.可视化操作界面：替代纯配置文件，支持网页可视化配置、运行、查看结果
2.全流程闭环展示：爬取 → MD 转换预览 → 字段配置 → 智能提取 → MongoDB 数据查看
3.轻量、无复杂依赖：基于模板项目现有前端栈开发，无需额外安装大型框架
4.响应式布局：支持 PC 端查看，满足现场演示验收

3.2、前端页面结构（共 4 个核心页面 + 1 个公共布局）
1. 首页 / 工作台（主页面）
•页面功能：任务总控制台，一站式发起爬取任务
•核心组件：
a.任务 ID 自动生成（显示不可编辑）
b.网址输入框：支持单行 / 多行输入（单个 / 批量网址）
c.开始爬取按钮 + 停止按钮
d.实时日志输出区（展示爬取进度、状态、成功 / 失败）
e.最近任务列表快捷入口
2. MD 内容预览页
•页面功能：展示爬取后的标准 MD 文件
•核心组件：
a.MD 原文展示区
b.MD 渲染预览区（标题、列表、表格正常渲染）
c.文件信息卡片：任务 ID、域名、爬取时间、存储路径
d.下载 MD 文件按钮
e.跳转「字段提取」按钮
3. 自定义字段配置与提取页（核心功能页）
•页面功能：可视化配置主 / 子字段 + 一键 AI 智能提取
•核心组件：
a.关联任务选择（下拉选择已完成爬取的任务）
b.字段配置区：
▪添加主字段（字段名 + 字段解释输入框）
▪为主字段添加子字段（字段名 + 字段解释）
▪支持删除、清空、保存配置
c.AI 提取参数配置区（可折叠）：
▪API 地址、超时时间、重试次数
d.开始提取按钮
e.提取结果展示区（整洁 JSON 格式，高亮显示）
4. 数据存储查看页（MongoDB 数据）
•页面功能：可视化查看已存入 MongoDB 的所有数据
•核心组件：
a.三个标签页对应三张表：
▪基础任务表
▪主字段表
▪子字段表
b.表格展示数据，支持按任务 ID 搜索
c.查看关联关系（主字段 ↔ 子字段）
d.数据类型标注（文本 / 数字 / 时间 / 数组）

3.3、前端功能要求
1.配置化界面
￮所有爬取地址、字段规则、API 参数全部在前端配置
￮无任何硬编码，配置自动传给后端
2.状态反馈
￮加载动画、成功 / 失败提示、错误信息弹窗
￮异步任务不阻塞页面操作
3.数据校验
￮网址输入格式校验
￮字段名非空校验
￮API 配置合法性校验
4.操作流畅
￮单页应用体验，页面无刷新切换
￮按钮状态禁用 / 启用自动控制
3.4 爬虫开发（30 分）
功能要求：
•支持自定义爬取网址（单个/多个）
•完整爬取网页核心内容后，精准转换为 MD 格式存储
MD 转换要求：
•保留网页层级结构（标题 ##/###、列表、表格等）
•过滤广告/无关链接/重复内容
MD 存储要求：
•文件命名规范：{任务 ID}_{网址域名}_{爬取时间}.md
•支持本地存储 +  （文本）双存储
技术要求：
•处理反爬机制（请求头配置、请求间隔）
•支持网页编码自动识别，避免 MD 内容乱码
•无强制技术栈限制

3.5自定义字段提取（30 分）
功能要求：
•开发自定义字段智能提取模块
•支持用户自定义字段及字段解释
•调用 new-api 中的模型，理解字段语义，从 MD 格式内容中精准提取对应字段值
核心要求：
•字段自定义：支持用户添加自定义主字段、子字段，并为每个字段填写字段解释
￮示例：商品价格 字段解释为 网页中展示的商品实际售价，不含运费、优惠券等附加费用
•智能提取规则：基于 new-api 模型对字段解释的语义理解，自动生成提取规则
•数据清洗：过滤 MD 中冗余空行、无意义字符，输出整洁的 JSON/BSON 结构化数据
•模型交互：支持配置 new-api 的调用参数（接口地址、超时、重试次数等）
