# 测试要求

## 🚨 强制性质量要求

### 1. 完整功能闭环（必须）

- ✅ POC 可以简化设计，但必须保证功能完整可运行
- ✅ 所有 P0 功能必须实现并通过测试
- ✅ 核心用户流程必须能够端到端执行
- ❌ 禁止"只写 UI 不集成 API"
- ❌ 禁止"只写代码不测试"
- ❌ 禁止"类型错误导致无法构建"

### 2. 问题返工机制（必须执行）

- ✅ Test 阶段发现的关键错误 → **必须**提交架构专家安排修复
- ✅ QA 阶段发现的阻塞问题 → **必须**触发返工流程
- ✅ 返工流程：架构专家分析 → 创建修复任务 → 分配专家执行 → 重新测试 → 重新 QA
- ❌ 禁止 QA 失败后直接生成报告而不修复
- ❌ 禁止测试失败后忽略问题继续推进

### 3. 构建成功门槛（最低标准）

- ✅ `npm run build` 必须成功通过
- ✅ TypeScript 类型检查必须通过（0 错误）
- ✅ 核心功能必须能够实际运行
- ⚠️ ESLint 警告可以容忍（但应 <100 个）
- ⚠️ 测试覆盖率可以 <100%（但核心代码 ≥90%）

### 4. 工作流纪律

- ✅ 每个阶段完成前必须验证该阶段的完成标准
- ✅ 发现问题立即记录到 active-bridge.md
- ✅ 阻塞性问题必须解决后才能进入下一阶段
- ❌ 禁止"赶进度"而忽略质量问题
