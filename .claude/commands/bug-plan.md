## 用户输入

```text
$ARGUMENTS
```

## 执行目标

先**定位错误来源**，再调用架构专家进行错误分析，输出完整修复方案后**等待用户确认**，确认后才安排专家执行修复。

## 执行步骤

### 步骤 0: 错误定位分析

分析用户提供的错误信息，确定：

#### 0.1 错误来源识别

根据错误信息特征自动识别来源：

| 错误特征 | 来源类型 | 典型示例 |
|---------|---------|---------|
| `Console Error`、`TypeError`、`ReferenceError` | **前端问题** | 浏览器控制台报错 |
| `Build error`、`Module not found`、`Webpack` | **构建问题** | npm run build 失败 |
| `API error`、`500 Internal`、`ECONNREFUSED` | **后端/API问题** | 服务器响应错误 |
| `Prisma`、`MongoDB`、`Database` | **数据库问题** | 数据库连接/查询错误 |
| `Test failed`、`E2E`、`AssertionError` | **测试问题** | 测试用例失败 |
| `Permission denied`、`ENOENT` | **环境/配置问题** | 文件权限或环境配置 |

#### 0.2 输出定位结果

```
🔍 错误定位分析

📋 错误信息：$ARGUMENTS

📍 错误来源：
- 类型：{{前端/后端/构建/测试/环境}}
- 位置：{{文件路径:行号}}
- 模块：{{涉及的模块}}

⚠️ 严重性：{{P0/P1/P2/P3}}

🎯 分析结论：
{{简要说明错误原因}}
```

### 步骤 1: 调用架构专家分析错误

请调用 architecture-planning-expert agent，深度分析以下错误：

错误内容：$ARGUMENTS

已识别信息：
- 错误来源：{{定位结果}}
- 错误位置：{{文件路径:行号}}
- 严重性：{{P级别}}

架构专家需要：

1. 分析根本原因
2. 设计修复方案
3. 确定需要调用的专家类型（frontend-expert/backend-expert）
4. ⚠️ **仅输出方案，暂不安排专家执行**

### 步骤 2: 输出方案并等待确认

分析完成后，输出完整修复方案，并在末尾添加：

```
⚠️ 请确认上述修复方案，确认后我将安排专家执行
```

**然后暂停，等待用户确认。**

### 步骤 3: 用户确认后执行

当用户回复"确认"、"可以"、"执行"等确认关键词后，按照 `/bug` 命令流程安排专家执行修复：
- 调用对应专家进行代码修复
- test-expert 进行 E2E 测试验证（可选）
- 验证构建成功
- 生成修复报告

## 与 /bug 的区别

| 命令 | 确认机制 | 流程 |
|------|---------|------|
| `/bug` | 无确认 | 定位→分析→直接执行修复 |
| `/bug-plan` | **强制确认** | 定位→分析→输出方案→确认→执行修复 |

## 使用示例

```bash
/bug-plan Console Error: TypeError: Cannot read property 'x' of undefined

# AI输出错误定位 + 修复方案 → 等待确认
# 用户回复"确认"
# AI开始安排专家执行修复
```
